# Security Policy

## Supported versions

Security fixes are applied to the latest commit on `main` and to the latest published release once releases are available.

## Reporting a vulnerability

Please do not disclose security-sensitive information in a public issue. Use the repository’s private GitHub security advisory workflow when available, or contact the maintainers privately through the organization’s GitHub profile.

Include the affected commit or version, operating system and architecture, reproduction steps, expected behavior, actual behavior, and any proof-of-concept needed to reproduce the issue. Please avoid including secrets or personal data in reports.

## Scope

Reports involving the compiler, generated assembly, native linking, installers, release artifacts, and CI workflows are in scope. Language-design suggestions and ordinary compiler bugs should be filed as public issues unless they expose a security impact.
